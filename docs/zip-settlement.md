# Zip 여행 경비 정산 (2026-10-20, 로컬)

## 사용 흐름
최종 일정의 ‘여행 장소’ 오른쪽 **+ 정산하기** → 현재 방의 코스·일차·멤버 불러오기 → 장소별 지출 또는 기타 지출 입력 → 내역 확인·수정 → 자동 정산 계산 → 송금 안내.

## 사용자 확인 규칙
- 실제 방 멤버가 지출을 공유·저장한다. 모든 참여 멤버가 추가·수정·삭제할 수 있다.
- 원화 정수 금액만 허용한다. 한 지출의 대표 결제자는 1명이며 반드시 분담 인원에 포함한다.
- 참여 인원 기본값은 전체 멤버다. 제외할 멤버만 해제한다.
- 금액을 참여 인원으로 균등 분배한다. 나머지 1원은 서버에서 고정한 멤버 순서(가입순, 같은 시각이면 회원 ID 순)대로 배정한다. 각 지출 분담액의 합계는 결제 금액과 정확히 같다.
- 지출마다 참여자를 저장하므로 나중에 새 멤버가 들어와도 이전 지출 분담액은 자동 변경되지 않는다.
- 실제 송금·송금 완료 확인·결제 연동은 없다. 중복 경고·환불 처리·수정 이력 UI·통계는 이번 범위에서 보류한다.

## 화면 기능
- 장소별 항목: 금액·날짜·분류·대표 결제자·참여자·메모 입력.
- 기타 항목: 택시비·주차비·통행료·기타 분류 선택.
- 내역: 날짜별·장소별·참여자별 결제 내역, 개인별 결제/분담 요약, 검색, 전체 합계, 수정·삭제 확인.
- 결과: 전체 지출 합계, 보내는 사람/받는 사람/금액, 개인별 결제액·부담액·차액. +는 받을 금액, −는 보낼 금액.
- 기존 보라색 테마·하단 고정 메뉴를 유지한다. 실제 장소 사진이 없으면 기존 준비 중 이미지를 사용한다.

## 저장·계산
- 기존 zip_rooms.payload.expenses를 사용하며 새 테이블·스키마·RLS를 추가하지 않았다.
- 서버에서 회원 인증·방 참여·입력 값·일정 장소를 검증한다. 개인의 이름을 클라이언트 입력으로 신뢰하지 않는다.
- revision 비교로 동시 변경을 감지한다. 충돌 시 최신 방 정보를 읽고 사용자가 다시 시도한다. 일정·투표 변경 시 지출을 보존한다.
- 삭제한 지출은 내부 삭제 표시를 남겨 합계·결과에서 제외한다. 삭제 이력이나 복원 UI는 이번에 추가하지 않았다.
- 원 단위 정수만으로 계산하며 지출당 1~999,999,999원, 방당 최대 500개 기록을 허용한다.
- 순차액을 상계해 송금 안내를 만든다. 비제로 잔액 인원 16명 이하에서는 최단 송금 조합을 탐색하되 계산 시간이 길면 유효한 간소화 조합을 사용한다. 큰 인원이나 시간 제한 시 최소 횟수 보장은 하지 않으며 화면에도 간소화 안내를 표시한다.
- 결과는 최신 지출을 계산한 값이다. 방 revision이 달라지면 이전 결과 대신 재계산을 안내한다.

## 검증 결과
- 로컬 빌드 통과. 기존 큰 청크 안내는 남아 있다.
- Backend 전체 72개 실행: 71개 통과, 기존 1개 건너뜀.
- 균등 배분·나머지·1원·잘못된 금액/날짜/멤버·결제자 포함·이전 멤버 보존·합계/차액 보존·최소 조합 및 무작위 50회 계산 검증.
- 실제 API 코드를 격리된 메모리 DB와 연결해 모바일 브라우저 검증: 버튼 위치 → 장소 지출 120,000원/4명 → 기타 지출 25,000원/3명 → 결제자 변경·한 명 제외 → 25,001원 수정 → 날짜별/장소별/참여자별 조회 → 합계 145,001원 → 차액 송금 38,334원+38,333원+13,333원 확인 → 기타 지출 삭제 후 120,000원 재계산 확인.
- 브라우저 콘솔 경고·오류 없음.
- 실제 회원 방에는 테스트 지출을 저장하지 않았다. 여러 실제 회원 계정·기기에서의 공유 저장 검증은 미실행이다.
- 로컬 API만 재시작했다. GitHub 푸시·운영 배포는 하지 않았다.
