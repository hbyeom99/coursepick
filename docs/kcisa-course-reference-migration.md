# 문화정보원 장소 → 카카오 참조 교체 (2026-10-23)

사용자는 문화정보원 출처 장소 제거 전에 해당 장소가 연결된 가상297개·기획2개의 코스를 카카오 API로 대체하도록 요청했다. 동일 장소로 판정되지 않은 항목은 원래 장소를 유지한다. 장소 삭제는 아직 수행하지 않았다.

## 반영

- `public.courses.schedule`의 대상 방문을 `place_id` 대신 `kakao_ref`(placeId/day/query/category/page)로 저장한다. `place_ids`에는 남은 기본 DB 장소만 유지한다. 기본 장소를 모두 대체했다면 cover_place_id는 null이며 기존 코스 사진 로직이 참조 사진을 선택한다.
- `editorial_courses.days`의 확정 방문은 place_id를 제거하고 kakaoRef를 연결한다. visit_id·day·시간·활동·원래 이름·업로드 이미지·사진 메타데이터를 유지한다.
- Backend 검증과 프런트 courseService 변환을 확장해 기존/혼합/카카오 전용 코스를 지원한다. 카카오 일정의 방문 시간은 stopDetails, 순서는 itineraryOrder로 전달한다.
- 기획코스 편집본 저장 시 이미 존재하는 `/images/editorial/user-<hash>.<ext>` 업로드 이미지를 보존한다. 외부 조회 사진 URL의 저장은 허용하지 않는다.
- 서버 조회본문/카카오 좌표/외부 사진은 DB에 저장하지 않는다. native→ref 대응 및 원본 백업은 git 제외된 outputs 아래에서 관리한다.

## 실행 및 결과

1. `outputs/review-kcisa-removal.py`: 삭제 후보16,397개 백업 및 코스 영향 분석. 다른 출처의 보강421개는 삭제 후보 제외.
2. `outputs/match-kcisa-kakao.py`: 중복 제외424개를 카카오 검색과 대조. 정확히 같은 이름+150m 이내 또는 정확히 같은 주소+1km 이내의 단일 후보만 자동 확정. 2.1초 간격 및 기존 프로세스 호출 제한 적용.
3. 사용자가 `backend/community_kakao_references.sql`을 Supabase에서 직접 실행하고 Success를 알렸다. 실제 1개 코스 교체와 재조회로 호환을 확인했다. MCP SQL은 권한 거부 상태였다.
4. `outputs/apply-kcisa-kakao.py --apply`: 행별 백업 후 원본 일정이 그대로인 경우에만 조건부 갱신한다. 갱신 결과를 다시 조회해 확인한다. 재실행 시 이미 교체된 방문은 제외한다.
5. `outputs/verify-kcisa-replacement.py`: 원본과 전체 코스를 비교. 확정225장소/254방문을 가상191개·기획2개에 교체. 미확정199개(추가검토93,검색결과없음106) 참조는 보존. 가상680개·기획10개 유지. 방문 순서·일정·업로드사진 등 비교 오류0. 장소 삭제0.

검토 결과: `outputs/kcisa-removal-2026-10-23/카카오_교체_검토.html` 및 `replacement-verification.json`.

## 미완료 및 배포

### 후속 199개 재대조 (2026-10-23)

- 사용자가 동일 이름·1km 이내 단일 후보와, 카페/cafe 접두·접미 차이만 있고 업종이 같으며 30m 이내인 단일 후보를 승인했다.
- 199개 전체를 지역명 축약·장소명 단독 등으로 재검색했다. 기존 검색어 후보 재확인 및 명칭 검토를 포함한 카카오 검색 호출은 371회다. 응답 본문·좌표·외부 사진은 영구 저장하지 않았다.
- 사용자 추가 승인: 송산근린공원→송산공원, 소룡동시민체육공원→소룡시민체육공원 본체, 황령산전망대→황령산전망쉼터, (주)선유유람선→선유유람선, 미친VR 광주충장로점→미친VR 광주충장점. 남산야외식물원의 주차장 후보는 전환하지 않았다.
- 신규 40개 장소·42개 방문을 가상 코스 39개 및 기획코스 1개에 반영했다. 기존 225개와 합쳐 장소 265개·방문 296개가 전환됐다. 미전환 159개는 후보 검토 64개·일치 후보 없음 95개로 보류했다. 이번 추가 삭제는 0개다.
- 전부 카카오 참조인 코스에서 예전 `cover_place_id = ANY(place_ids)` 검사에 걸렸다. 빈 배열에서 이 검사가 false가 되는 문제를 `community_kakao_cover_fix.sql`로 수정했고, 사용자가 SQL Editor에서 직접 실행했다. UI에 새 검사 정의가 표시된 것을 확인하고, 실제 전용 코스 갱신 성공을 확인했다. 최초 혼합 참조 SQL에도 같은 수정을 포함했다. RLS/권한 변경 없음.
- 백업과 전체 코스를 비교하여 코스 수·순서·시간·기획코스 업로드 사진 등 비교 오류 0. 일정 단위 테스트 3개 통과. 실제 로컬 API와 프런트 변환에서 680개 전체 코스 정상 조회(카카오 포함 216개 코스, 가상 코스 카카오 방문 293개). 기획코스 카카오 방문 3개는 별도다.
- 중단된 로컬 API/웹 서버를 기존 실행 도구로 복구하고 홈 화면 표시를 확인했다. 콘솔에는 Vite 개발용 WebSocket/HMR 연결 경고가 남아 있으며, 이번 DB 전환과 별개로 기록한다.
- 결과: `outputs/kcisa-removal-2026-10-23/second-pass-verification.json`, `미전환_199개_재대조_결과.html`. Git 커밋·푸시·배포 없음.

### 후속 삭제 (2026-10-23)

- 사용자가 문화정보원 출처 삭제를 요청하고, 카카오 참조로 전환한 장소는 제외하도록 지시했다. 미전환 199개는 기존 코스 연결 때문에 보류하는 선택을 확인했다.
- 원본 장소 16,397개 중 전환 원본 225개 및 courses/editorial_courses/member_data/zip_rooms 연결 장소를 합쳐 425개를 보호했다. 15,972개 삭제 후 재조회로 잔여 425개를 확인했다.
- 연결 조회에서 발견한 장소는 모두 보존했다. 참조 수는 courses 199, editorial_courses 1, member_data 1, zip_rooms 4로, 테이블 간 및 전환 원본과 중복된다.
- 삭제 전 대상 장소 및 연결 테이블을 `outputs/kcisa-removal-2026-10-23/delete-unlinked/`에 백업했다. 해당 폴더에는 회원 데이터가 포함되므로 Git/배포/외부 공유 대상에서 제외한다.
- 삭제 후 네 연결 테이블 전체를 삭제 전과 비교하여 변경 없음, 보호 장소 누락 없음, 삭제 오류 0을 확인했다. 카카오/TourAPI 호출 0. 세부 결과는 같은 폴더의 result.json이다.
- 아래의 “아직 places를 삭제하지 않는다”는 초기 교체 단계 기록이며, 이 후속 삭제 결과로 대체한다. 미확정 연결 장소의 삭제 보류는 유지한다.

- 남은199개는 이름 차이·거리·동명 후보 또는 검색 결과 없음 때문에 자동 교체하지 않았다. 예: 영일대해수욕장 정확 이름 후보는 기존 좌표와247m 차이이며 주소도 정확히 같지 않아 현재 기준으로 검토 대상이다.
- 전체 삭제를 진행하면 남은 참조가 끊기므로 아직 places를 삭제하지 않는다.
- 변경된 DB 코스를 배포 앱에서 읽으려면 Backend/Frontend 호환 코드의 동시 배포가 필요하다. 사용자 지시 없이 커밋·푸시·배포하지 않는다.
- 단위/변환 테스트 및 Vite 빌드 통과(기존 대용량 청크 경고). 실제 API 전체 코스 변환과 DB 전수 비교로 확인했다. Work 브라우저 제어 비활성화로 이번 변경의 브라우저 콘솔·실제 화면 확인은 수행하지 못했다.
