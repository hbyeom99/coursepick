# 코스픽 워크플로우 발표 멘트

예상 1분 30초~2분. 발화 속도에 따라 달라집니다.

코스픽의 서비스 흐름은 크게 프론트엔드, 백엔드, 그리고 데이터와 외부 API의 세 영역으로 나눌 수 있습니다.

먼저 위쪽 프론트엔드입니다. 사용자는 회원가입 후 네 가지 여행 성향을 입력하거나, 비회원으로 코스를 둘러볼 수 있습니다. 키워드를 검색하면 앱은 검색 조건에 맞는 장소를 찾고, 사용자의 성향과 이동 동선, 장소 중복을 고려해 코스를 제안합니다. 이 계산은 별도 작업 스레드인 웹 워커에서 처리해 화면 조작을 방해하지 않도록 구성했습니다.

가운데 백엔드는 화면과 데이터 사이를 연결합니다. 로그인 상태와 접근 권한을 확인하고, 장소와 코스 정보를 조회합니다. 카카오 검색 요청의 횟수를 제한하며, 이동 정보 조회와 코스 저장, Zip 공동 일정의 동시 수정도 처리합니다.

아래쪽은 데이터와 외부 API입니다. 수파베이스에는 회원 성향, 검토된 장소, 코스와 여행 기록을 저장합니다. 한국관광공사 TourAPI는 별도 수집과 검토를 거쳐 장소 DB를 보완하고, 카카오 API는 실시간 장소 검색과 이동 정보를 제공합니다.

마지막으로 사용자는 추천 코스를 편집하고 저장하거나 Zip에서 함께 일정을 만들 수 있습니다. 정리하면, 코스픽은 검토된 장소 정보와 실시간 검색을 바탕으로 개인의 취향에 맞는 여행 계획을 만드는 서비스입니다. 현재 추천은 외부 생성형 AI가 아니라 규칙과 성향 점수로 작동합니다.

## 발표 시 화면 짚는 순서

- 위쪽: 사용자의 탐색·검색·추천·저장 흐름
- 가운데: 인증·조회·요청 제한·권한 검증
- 아래쪽: Supabase·Kakao·TourAPI의 역할

## 이미지 설명 범위

로컬 구현 기준 대표 연결입니다. TAGO는 대중교통 보조 조회이며 모든 이동수단의 실시간 경로를 보장한다는 의미는 아닙니다. Google 별도 보조 조회와 세부 저장 정책은 발표 가독성을 위해 생략했습니다. 회원가입·성향 입력은 검색의 필수 전제 조건이 아니며 비회원 탐색도 허용합니다. 이미지의 연결선은 대표 요청/응답을 나타내며 개인 성향이 외부 장소 API에 전송된다는 뜻은 아닙니다.
