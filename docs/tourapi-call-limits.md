# TourAPI 호출 제한

- 기존 nationwide_import.Collector.call의 실제 외부 요청 직전에 적용한다.
- Kakao와 동일한 60초 이동 창: 호출 주체별 30회, 프로세스 전체 300회. 공급자별 카운터는 독립이다.
- 수집기는 HTTP 사용자 주소가 없으므로 collector라는 공통 주체를 사용한다. 같은 프로세스의 여러 수집기 인스턴스도 이 30회 한도를 공유한다.
- 모든 재시도는 별도 외부 요청으로 계산한다. SQLite 캐시 적중은 외부 호출이 없어 차감하지 않는다.
- 초과 요청은 외부 전송 전에 QuotaError로 중단하고 재시도까지 남은 초를 안내한다. 기존 수집 진행 상태와 캐시는 유지한다.
- 기존 0.25초 최소 간격과 공급자의 일일 한도·오류 처리는 유지한다.
- 프로세스 메모리 제한이다. 별도 프로세스·여러 서버의 합산 전역 제한 또는 TourAPI 계정의 공식 쿼터가 아니다. 프로세스를 재시작하면 카운터가 초기화된다.
- 홈 검색은 기존 TourAPI 수집 DB를 사용한다. 이번 변경은 TourAPI 실시간 홈 검색을 새로 추가하지 않는다.
