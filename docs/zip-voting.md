# Zip 코스 투표 (로컬, 2026-10-20)

## 이용 흐름
추천 코스 → 투표 진행 → 카드 우측 흰색 버튼으로 후보 2~10개 선택 → 선택한 후보로 투표 진행 → 코스 투표 팝업에서 하나 선택 → 투표하기 → 완료 팝업 → 결과 확인 → 1위 코스 최종 일정 적용 → 교체 확인 → 최종 일정 탭.

- 기존 실제 회원 공동 방에 연결한다. 참여 멤버는 투표마다 1인 1표이며 제출한 표를 중복 제출할 수 없다.
- 투표 시작 시 참여 중인 멤버를 대상자로 고정한다. 이후 참여한 멤버는 다음 새 투표부터 참여한다.
- 전원 참여 전의 결과는 진행 중으로 표시하며 최종 일정 적용을 허용하지 않는다.
- 공동 1위이면 동수표 안내와 재투표 버튼을 표시한다. 공동 1위 후보만 남기고 표를 초기화하며, 같은 대상 멤버가 다시 1표씩 투표한다. 재차 동수표이면 같은 방식으로 반복한다.
- 참여 멤버 누구나 투표를 시작하거나 동수표 재투표를 열 수 있다. 기존 공동 일정 편집 권한과 같이 1위 코스 적용도 참여 멤버가 할 수 있다.
- 1위가 확정되면 최종 일정 교체를 확인한 뒤 코스 제목·장소·방문 순서·일차·시간을 적용한다. 방의 시작일을 유지하고 코스 일수가 더 길면 기간을 연장한다. 기존 일정의 장소는 교체되며 필요한 빈 일차는 유지한다.
- 적용한 투표는 재적용하지 않는다. 새 투표를 시작할 수 있다.
- AI 코스 재조합은 사용자 확인대로 준비 중 버튼이다.

## 저장과 동시 수정
기존 zip_rooms.payload.poll에 투표 스냅샷을 저장한다. 새 테이블·DB 스키마·RLS 변경은 없다. 일정 변경 시 기존 payload의 투표를 보존한다.

회원 인증과 방 참여 권한을 확인하며, revision 비교 후 저장해 동시 투표·일정 변경 충돌을 409로 반환한다. 프런트엔드는 최신 방을 읽고 다시 시도하도록 안내한다. 진행 중인 투표는 방 화면이 보일 때 5초 간격으로 갱신하며, 늦게 도착한 이전 revision은 반영하지 않는다.

응답에는 집계와 본인의 선택만 포함하고 다른 멤버의 개별 선택은 보내지 않는다. 다른 멤버 수·후보 변경이 투표 도중 기존 표의 의미를 바꾸지 않도록 대상자와 후보를 고정한다.

## 검증
- 로컬 빌드 통과 (기존 큰 청크 안내는 남아 있음).
- Backend 전체 59개: 58개 통과, 기존 1개 건너뜀.
- 실제 투표 API를 격리된 메모리 DB와 연결한 브라우저 검증: 후보 선택 → 투표 완료 → 1:1 동수표 → 공동 1위 재투표 → 2:0 확정 → 일정 교체 확인 → 최종 일정의 1일차·2일차 장소·시간 확인.
- 모바일 화면 확인, 검증 화면 콘솔 경고·오류 없음.
- 실제 회원 방에는 테스트 표나 일정을 저장하지 않음. 실제 회원 여러 계정·기기에서의 운영 검증은 미실행.
- 운영 배포·GitHub 푸시 없음. 로컬 API 서버만 재시작.

기획안의 원본 사진은 제공되지 않아 기존 장소 사진을 사용한다. 증빙 화면은 실제 DB와 분리된 검증 화면임을 상단에 표시한다.
