# 카카오맵 공개 페이지 대표 사진

장소 상세의 `https://place.map.kakao.com/{숫자 ID}` 링크를 기준으로, 기존 사진이 없을 때 공개 페이지의 `og:image` 대표 사진을 조회한다. 공식 Local API 사진 기능이나 갤러리 전체 수집은 아니다.

- Backend: `GET /api/kakao/places/{place_id}/photo`. 기존 Kakao 호출 제한 적용, HTML 최대 1MB/8초, 리다이렉트 금지. 숫자 ID로 고정 호스트만 접속한다.
- 카카오 CDN의 장소 사진 주소만 반환하고 정적 지도·다른 호스트는 제외한다.
- 사용자 후속 승인(2026-10-23)에 따라 사진 조회 결과만 서버·브라우저 메모리에서 재사용한다. 성공 URL은 1시간, 사진 없음은 10분, 일시 오류는 1분이다. DB·파일·브라우저 영구 저장소는 사용하지 않고 페이지 본문·이미지 파일은 보관하지 않는다. HTTP 응답은 no-store를 유지한다.
- 기존 사진을 우선하며, 조회 실패·외부 이미지 로딩 실패 시 공통 대체 이미지를 사용한다. 출처 링크는 카카오맵으로 표시한다.
- 카카오맵 링크가 장소 ID 대신 좌표 링크만 있는 장소는 자동 추출하지 않는다. Google 상세에는 적용하지 않는다.
- 공개 페이지 구조 변경이나 외부 이미지 차단으로 조회가 중단될 수 있다. 운영 사용 정책 문의는 사용자가 별도 진행하기로 했다.

2026-10-23 확인: URL 검증·파서 검사 통과, 아비오(741116265) 실제 조회 성공, 실행 중인 localhost:8000 API 응답 성공. 기존 KakaoPlaceDetails를 렌더링한 `/outputs/photo-preview-check.html`에서 카카오 CDN 이미지 로딩(800px)과 브라우저 경고·오류 없음 확인. Vite 프로덕션 빌드 성공(기존 대용량 청크 경고 있음). 전체 페이지별 동작 검증은 수행하지 않았다.

## 호출 최소화 최적화

- 기존 이미지 우선: 실제 이미지가 있으면 외부 조회 제외. 공통 대체 이미지와 data SVG만 미등록으로 취급한다. 기존 사진 로딩 실패를 이유로 자동 외부 검색하지 않는다.
- 같은 ID 요청은 브라우저 Promise와 서버 Future로 통합한다. 컴포넌트를 닫아도 공유 요청을 취소하지 않으며, 화면 업데이트만 해제한다.
- 서버·브라우저 캐시는 각 최대512개다. 서버 외부 조회는 최대3개 동시, 처리 대기 ID는 최대32개로 제한한다. 캐시 사용은 외부 호출 제한 카운터를 소비하지 않는다.
- IntersectionObserver로 실제 스크롤 영역에 보일 때 조회한다. 숨긴 탭에서 새 조회를 시작하지 않으며 화면에 복귀해도 유효 결과가 있으면 재사용한다.
- 서버는 캐시의 남은 유효시간을 반환하므로 클라이언트가 오래된 결과를 추가1시간 연장하지 않는다.
- 기존 상세와 카카오 장소 추가 카드·개인 일정·Zip 최종 일정의 카카오 이미지에 공통 로직을 연결한다. 기존 Google 사진은 유지한다.
- 사진만 비동기로 교체하며 기존 이미지 영역 크기와 30초 페이지 로딩 상한을 유지한다. 카카오 ID가 없는 DB 장소를 자동으로 이름 검색해 매칭하는 추가 API 호출은 하지 않는다.
- 프로세스/탭별 임시 캐시다. 서버 재시작·다중 서버·새 탭에서는 다시 조회할 수 있다. 전역 공유 캐시가 아니다.

검증: `tools/test_place_photo_cache.py`의 만료·동시8건중복통합·캐시용량·동시외부최대3건 검사 통과. 브라우저 모의 응답 화면에서 동일 ID 두 카드=1조회, 재마운트 후에도1조회, 기존 이미지 ID=0조회, 화면 밖 ID=0조회 후 스크롤 시1조회를 확인했다. 실제 API에서 아비오 사진 조회 후 남은 TTL 재사용 응답 확인. 실제 공통 상세에서 사진 표시와 콘솔 오류 없음 확인. Vite 빌드 통과(기존 청크 경고); 이후 IntersectionObserver 초기 판정 보완은 로컬 Vite에서 확인했다.

## 양연화로 사진 표시 보완

카카오 장소1619274444는 사진 URL 조회 응답이 정상임에도 최초 브라우저 이미지 로딩 실패 뒤 대체 이미지가 유지되는 현상을 재현했다. 서버 GET은 JPEG 200으로 응답했고 브라우저 직접 이미지도 후속 조회에서는 정상 로딩돼, 고정된 차단 정책이나 사진 부재로 단정하지 않았다.

공통 이미지 컴포넌트는 최초 오류 시700ms 뒤 딱1회 재시도한다. 카카오 C형 썸네일이면 같은 이미지의 R800형으로 전환하고 referrerPolicy를 no-referrer로 설정한다. 이 재시도는 사진 조회 API를 다시 호출하지 않는다. 성공한 실제 이미지 URL을 화면에 반영하고 언마운트·30초 제한 시 재시도를 정리한다. 그래도 실패하면 대체 이미지를 유지한다.

## 코스 대표 이미지 및 외부 원본 확대 (2026-10-23 후속 승인)

이 절이 이전의 원본 호스트 허용목록 설명을 대체한다. 사용자는 카카오 상세 페이지의 대표 사진을 원본 서버 제공자와 무관하게 포함하도록 승인했다. 서버는 고정된 카카오 장소 페이지의 og:image만 읽고, 카카오 썸네일의 fname 또는 직접 이미지 URL이 공개 HTTP(S) 주소인지 확인한다. 네이버·다른 외부 호스트라는 이유로 제외하지 않는다. 로컬/사설 주소·인증정보 포함 주소·정적 지도는 제외한다. 이미지 파일은 브라우저가 로딩하고 성공 여부를 판단하며 서버는 원본 이미지 서버를 추가 조회하지 않는다. 작성자나 소유자를 호스트 이름으로 단정하지 않고 네이버 호스트는 ‘네이버 이미지 서버 · 카카오맵 경유’로 표시한다.

코스 카드 흐름:
1. 화면에 보이는 카드의 명시적 대표 사진을 시도한다.
2. 없거나 이미지 로딩에 실패하면 기존 DB 장소 사진 후보로 넘어간다.
3. 그다음 kakaoPlaceRefs를 일정 순서대로 확인한다. 사진 URL은 기존 공통 요청·메모리 캐시를 재사용한다.
4. 사진 없음·조회 실패·이미지 로딩 최종 실패 모두 다음 후보로 넘어간다. 처음 정상 로딩된 사진에서 멈춘다.
5. 모든 후보가 실패하면 공통 대체 이미지를 표시한다. 페이지 로딩은 최대30초이며 뒤늦은 사진은 해당 영역만 교체한다.

외부 사진 URL을 코스·장소 DB에 복사하지 않는다. Google 참조와 정보는 이 경로에 포함하지 않는다. 별도 Naver 검색 API·블로그 본문 수집·API 키 설정을 추가하지 않는다. 전체 사진 갤러리를 수집하는 기능은 아니다.

검증: 공개/사설 URL·네이버/기타 공개 호스트 검사 통과. CourseCoverPhoto 실제 컴포넌트에서 러너펍 신림점 사진 표시, 사진 없음→호멜맥주, 이미지 로딩 실패→호멜맥주 전환을 확인했다. 두 카드의 호멜맥주 조회는1회였으며, 기존 사진이 있는 별도 카드의 다음 카카오 후보 조회는0회였다. 브라우저 콘솔 오류 없음. Vite 빌드 통과 후 출처 문구와 Backend 공개 호스트 판정만 추가 보완했으며 해당 변경은 별도 검사·로컬 Vite에서 확인했다.
