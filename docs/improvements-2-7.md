## 적용

2. 업종 확인, 자연현상 부정 문장 배제, 구조화된 조건 또는 명시 태그 확인, 축제·팝업 운영기간 필요 조건을 추가했다. 운영기간은 기존 seasonEligibility에서 현재 날짜와 비교한다. 명시 태그의 원자료 자체가 틀릴 수 있으므로 무오류를 보장하지 않는다.
3. tools/search_regression.mjs에 맥주 정확/하위/제목, 오로라 오분류, 효도여행 활동 제한, 무료주차 근거, 종료 행사, 후보 없는 생성 등을 검사한다.
4. AI·페르소나 생성은 courseGeneration.worker.js에서 계산한다. 변경된 검색은 이전 Worker를 종료하며, 결과는 메모리에서만 사용한다. Worker 실패 시 오류를 표시하고 메인 스레드에서 동기 생성으로 되돌리지 않는다. 새 외부 API 호출을 추가하지 않았다.
5. 지도는 시도 기본 경계와 17개 시군구 파일, 주소는 20개 지역 파일로 분리했다. 해당 범위가 필요한 화면에서 동적 로딩한다. 원본 데이터는 보존하고 런타임/배포 입력에서 제외한다. 통합 검사는 분할 전후 내용 동등성을 확인한다.
6. 생성 상태 처리·사용자 정렬·지역 주소 로딩·지도 컴포넌트·검색 카드 CSS를 별도 역할 파일로 분리했다. 기존 App의 모든 화면을 대규모 재작성하지는 않았다.
7. npm run check (또는 python tools/check_project.py) 한 명령으로 비밀값 패턴 검사 → 지역 데이터 동등성 → 검색 규칙 일치 → 모의 백엔드 테스트 → 검색 회귀 검사 → Vite 빌드 → 빌드된 Worker 실행 검사를 순차 실행한다. 실패하면 즉시 중단한다. 설치·DB·푸시·배포는 실행하지 않는다. 기존 Python 의존성이 설치된 환경과 Node가 필요하며 NODE_BINARY로 Node 경로를 지정할 수 있다.

## 사용자 코스 표시

기존 사용자 코스를 먼저 보여준다. 검색 일치 등급/성향 정렬은 기존 그룹 안에서 유지한다. 5개 미만이면 부족한 만큼만 서로 다른 가상 페르소나 예시로 보충한다. 예시는 뒤에 표시하며 가상 사용자 예시 배지를 붙인다. 적합한 후보가 없으면 채우지 않는다. DB 자동 공개 저장은 하지 않는다.

## 제한

지도/주소 분할과 Worker 도입 후에도 일부 큰 번들 경고는 남는다. 실제 모바일 터치·브라우저 속도 수치·콘솔 검증은 브라우저 사용이 비활성화되어 확인하지 못했다. Worker 자동 검사는 실제 빌드 산출물을 Node의 별도 스레드에서 실행한 것으로 브라우저 CSP/모바일 호환성 검증을 대신하지 않는다.
